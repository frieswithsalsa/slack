# Чеклисты детального прохода по файлам

## 1. Производительность

- Нет N+1.
- Нет лишних ререндеров/циклов в hot path.
- Нет блокирующих тяжелых операций.

## 2. Контракты и дизайн-система

- При рефакторинге не теряются поля публичных контрактов, включая служебные пропсы.
- Иконки именованы семантически, без дублей.

## 3. Тесты (скриншотные/юнит)

- В скриншотных тестах для экранов использовать `splitIntoViewport`.
- При работе с моками в скриншотных/юнит тестах использовать `immerjs`.

## 4. Монорепо и слои

- Проверять границы между пакетами/слоями.
- В новом коде не должно быть импортов из `view/*` в `app/*`.
- Фиксировать риски циклических зависимостей.

## 5. Границы замечаний

- Не предлагать security-hardening правки «на всякий случай» (доп. валидации, ограничения длины, экранирование), если
  нет явного требования.
- Не поднимать security-замечание без подтвержденного риска в текущем контексте и/или без нарушения проектного
  контракта.
- Security-комментарии допустимы только при фактическом дефекте или явном требовании из задачи/документации.
